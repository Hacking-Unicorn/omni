## 1. Mission

Replace all Rust with Omni, leaving Rust only as a thin Stage-0 seed (VM, the ISA table and decoder the VM needs, a thin host shim for files/sockets/clock, and a thin CLI launcher — a proposal, not a locked seed list). Omni is AI-first: add nothing for human readability. The real artifact is the `u16` token stream, not the `.omni` surface text.

Primary goal as stated for the crew: the Rust host shrinks until it is only that seed. HTTP, DB/KV, and the Repair Agent belong in core Omni on purpose; they are not supposed to stay in the seed.

## 2. Sacred invariants

Never violate these, and do not suggest violating them:

- 192 SSA values and **16 labels** per function. (Surface `.omni` today still numbers labels from 1 and rejects the 16th; that is C4's fix, see §6. Assembly with label ids 0..15 already works on all four backends.)
- 64-deep call stack.
- Eager argument evaluation.
- No heap structs, hash maps, or GC. Flat linear arena only. Compile-time offset constants are allowed. An arena-backed sorted array with binary search is allowed (decided for KV/DB).
- No recursion in core `.omni`. Use iterative state machines with explicit worklists. Many small helpers is the intended style.
- The 128-opcode table `0x7F00..0x7F7F` is full and is never renumbered.
- 4-backend parity on every commit: VM, x86-64 ELF, Stage-1, and Wasm.
- Zero external crates.
- Rerun every selftest suite after every commit. Stop and report before landing a change that would move a frozen hash, except for the single planned re-freeze below.

## 6. Decisions (including ones that were only made in chat)

Later chat decisions supersede a few "still open" rows in the committed `spec/m2/DECISIONS.md` and `spec/m3/DECISIONS.md`. Those files were not edited after M2-00 / M3-00. This section is the authority if they disagree.

### 6.1 Option A — new operand shapes on IGET/ISET

- 3-op `IGET buf, mode, off` with mode `-2`/`-4`/`-8` is an LE load of that width.
- 4-op `ISET buf, mode, off, val` with mode `-2`/`-4` is a patch.
- Strict bounds: `off >= 0 && off+width <= len`, with an overflow check.
- Surface forms: `ld_u16`/`ld_u32`/`ld_u64` and `st_u16`/`st_u32`/`st_u64` (WIP also introduces `ld_i*`/`st_i*` names; treat the WIP spellings as unverified).
- Existing `-9` mode is left exactly as it is.
- 2-op `IGET` is unchanged, because the Stage-1 image uses it 68 times. Changing that path would move `0xEAFC…`.

ISA-A (these shapes, plus byte readback on x86/Stage-1) is the current main-line work. ISA-B is next (not started on origin). C1–C4 wait until after ISA-A/B.

### 6.2 Lockstep overhead

Policy is **deferred to Caleb**. The shadow mode is already on as of `74a215c`. Do not change the overhead policy without him.

### 6.3 C1–C4

- **C1:** hash-pin selftest (assert the five FNV literals). Not landed as of `d2d6c13`. Vera dropped her own P0 so it would not collide with C1.
- **C2:** Stage-1 rejects `DROP`, `IMOD`, and the broken pack5 ops up front (hash-safe Rust-host gate), rather than silently mis-executing them. Not landed.
- **C3:** the verifier rejects non-trit values in both twins (hash-safe alternative to making AOT clamp, which would move hashes). Not landed.
- **C4:** the label cap is **16**. Vera found the emitter is fine: a 16-label assembly function with ids 0..15 is accepted by the Rust verifier, lockstep, the Phase-7 kernel, and the Omni engine, and runs identically on all four backends, with Stage-1 ELF == host ELF (`vera_harness.md` §3, `lbl16_asm_ids_0_15`). The real limit is the source compiler: it numbers labels from 1 at `omni_rust_bootstrap.rs:3587` (`next_lbl: 1`) and rejects the 16th with `BUDGET_EXCEEDED` at `:3646-3656` (`next_lbl > 15`, message still says "15 basic-block labels"). Confirmed at `d2d6c13` in this clone. C4 should fix that numbering, allow 16, reject 17. Legacy exemption: the Rust-built Stage-1 stream (about 83 IMM labels). Vera already has 15- and 16-label cases in the suite; 16-label surface is currently expected to be rejected, and must flip when C4 lands (XPASS discipline). A 17-label reject-on-all-backends case was requested; confirm it is present before treating C4 as done.

### 6.4 VM negative patch offsets

`iset_patch_i64` / ISET mode `-9` with offsets in `-8..-1` currently panics in the VM (`omni_rust_bootstrap.rs:1324-1326` at the review base; the panic string is a slice-index underflow). Decision: it becomes a **silent no-op**, not a panic. This is Ember's first fix. Hash-safe: the Stage-1 stream only patches in-range offsets 96/104.

### 6.5 Milestone 2

- Work lives in `pure/m2/`. `pure/compiler.omni` stays frozen.
- 3-op `RET buf, off, len`.
- `IGET` byte mode `-1`.
- u32 label entries.
- Native multi-function ABI with a 1 MiB stack arena.
- Wasm `CALL` is required for sign-off (M2-10, handed to Ember, starts after ISA-A).
- Label resolution copies Rust exactly: first definition wins; undefined labels are rejected.
- Multi-mode input window: **128 KiB** (O-3, decided later; the committed M2-00 still lists O-3 as open).
- Multi-mode arena layout: tokens `0x00000-0x20000`, labels `0x20000`, register state `0x24000`, output `0x28000`. Single mode stays byte-identical to today.
- Defaults decided after M2-00 was committed:
  - **O-5:** IMOD template left untouched; rejected via lint (avoid a Stage-1 hash bump).
  - **O-7:** multi-function only through the new entry point (no silent auto-route).
  - **O-4:** label ids `>= 4080` rejected in M2 now; Rust to be spec'd later.
  - **O-2:** Wasm checked via an in-guest hash.
- Still open: **O-1** (native trap exit codes), **O-6** (pack5 dynamic-index bloat), **O-8** (`validate_func_pack5_ops` monolith/workspace divergence).

M2-00 still says "15 usable labels"; that is superseded by C4 (16).
