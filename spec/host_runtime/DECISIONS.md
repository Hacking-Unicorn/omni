# Host-runtime port decisions (Ember Runtime, `ember/runtime-port`)

| ID | Decision | Source |
|---|---|---|
| HR-1 | Arena band `0x100000-0x2FFFFF` (2 MiB) is reserved for everything the host runtime allocates: VM interpreter memory, decoded instruction table, call frames, KV/DB slabs, request/HTTP buffers, bump heap (`pure/vm_*`, `pure/host_*`). Supersedes the earlier `0x100000-0x17FFFF`. M2 stays below `0x80000`; M3 owns `0x80000-0xFFFFF`. | Boss Lady, 2026-11-14 (widened same day); HANDOFF.md §6.6 |
| HR-2 | `DB_QRY` (`0x7F65`) miss returns `-1` (`OMNI_DB_QRY_MISS`), never `key*10`. `DB_GET` (`0x7F64`) miss also returns `-1` (`OMNI_DB_GET_MISS`), never `key*10`. | Boss Lady, 2026-11-14; HANDOFF.md §6.7 |
| HR-3 | KV/DB in core Omni uses an arena-backed sorted array with iterative binary search (no hash maps). | Boss Lady, 2026-11-14; HANDOFF.md §6.7 |
| HR-4 | `pure/host_runtime.omni` `omni_pure_host_kv_apply` (op 3 = query, returns `key*10`) and its embedded stdlib literal are left untouched: they are in `PURE_OMNI_CORE_SUITE_MODULES`, so editing them moves `0x78462AE4C81DF408`. Known guest/host difference: the guest model returns `key*10` for op 3 while the Rust VM returns `-1` on a miss. Fixed at the planned re-freeze, not before. | Boss Lady, 2026-11-14; hash policy HANDOFF.md §3 |
| HR-5 | Port-plan step 9 KV slice: `pure/host_kv.omni` (sorted array at band `0x1B0000-0x1EFFFF`, iterative binary search) runs in lockstep with the Rust VM KV arms (`run_host_kv_lockstep_selftests`, path `kv`). VM-only by design. **Open (proposed, not decided):** the Omni arena caps KV at 8192 entries (tag 3, store and charge unchanged) while the Rust `BTreeMap` is bounded only by the VM memory budget (16 B per `KV_PUT`, overwrites included); lockstep flags that divergence. `DB_UPD`/`DB_DEL` have no VM arm (Void), so no delete is ported. | Ember, 2026-11-14; decision needed before step 10 |
| HR-6 | Supersedes the open part of HR-5. Rust VM KV gets the same fixed cap as the Omni arena: `OMNI_VM_KV_MAX_KEYS = 8192` distinct keys (monolith and `omni-vm`). The 8193rd new distinct key is `error[BUDGET_EXCEEDED]` on both sides, checked before the 16 B charge, so store and charge stay unchanged; overwriting an existing key at the cap still succeeds. Selftest 13BE pins it in lockstep. | Boss Lady, 2026-11-14 |
| HR-7 | `DB_UPD` (0x7F66) / `DB_DEL` (0x7F67) stay Void no-ops in both Rust and Omni. Real update/delete semantics are a new feature for Caleb's hardening phase. | Boss Lady, 2026-11-14 |
