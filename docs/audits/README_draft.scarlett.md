# Omni

Omni is a 16-bit token-stream ISA (128 opcodes, `0x7F00..=0x7F7F`) with a capability / linear-ownership / taint verifier, a deterministic VM, `@PACK5` balanced-ternary packing, a `.omni` surface language, and native x86-64 ELF64 and WebAssembly backends for a documented opcode subset.

**Status, in one line:** this repository is a **Stage-0 Rust bootstrap**. Omni does not compile Omni yet. One real component has been ported to Omni (the token-stream verifier engine), and it is not on the default path. Everything else labelled "Pure-Omni" is a small decision kernel. Those kernels run in the VM, and Rust does the actual work around them. The tables below show which side runs each stage.

## Design constraints

These limits are intentional. They are not gaps waiting to be filled:

- Zero external crates. `Cargo.lock` lists only the eight workspace packages.
- 192 SSA registers and 16 labels per function, enforced by the surface compiler; 64-deep calls, enforced by the VM.
- Eager evaluation. No heap structs, maps, or GC in core `.omni`; data lives in flat byte buffers.
- No recursion in core `.omni` modules.
- The 128-opcode table is never renumbered.

## What runs where

### Runs as `.omni` guest code (executed by the Rust VM)

| Component | What it actually does |
|---|---|
| `pure/verifier_engine.omni` (1,034 lines, 58 functions, loops only, no recursion) | A real verifier that walks the `u16` stream. It checks capability, taint, linear/borrow state, SSA order, labels, and unknown opcodes. It is differentially tested against the Rust verifier on 77 cases (verdict, error code, and word offset). **It is not used by `run`, `eval`, `serve`, or `compile-*`.** It is also excluded from the 18-module suite below. |
| Phase 7 / A / B / C / D kernels, plus `pure/compiler.omni`, `pure/verifier.omni`, `pure/host_runtime.omni`, `pure/tooling.omni`, `pure/selfhost_suite.omni` | Small functions that map a few integers to an error or status code. Rust computes those integers. None of them tokenizes, parses, lowers, walks a stream, or does I/O. |
| `std/*.omni` (7 modules) and `pure/programs/*.omni` (6 programs) | Small but real library helpers and demo programs. The Rust pipeline compiles them and the VM runs them. |

On this commit, every `.omni` module except `verifier_engine.omni` is compiled from a **Rust string-literal copy** embedded in `omni-lang`, not from the file on disk. The on-disk files currently match those copies, ignoring comments and whitespace. Editing a file under `std/` or `pure/` alone does not change what gets built.

### Runs in the Rust host

| Stage | Notes |
|---|---|
| Surface lexer, parser, includes, macros, lowering to `u16` | The production compiler. `compile_omni_surface_via_pure_omni_frontend*` runs the Phase A kernel on `(source length, 0, 0)`, which can only reject empty input, and then calls the Rust compiler. |
| Production static verifier (`omni-verifier`) | Used by `run`, `eval`, `repl`, `harness`, `agent-driver`, and `serve`. `compile-elf` and `compile-wasm` use it through the AOT emitters. `compile-surface` runs only the Phase 7 summary kernel before it writes `.omni_bc`. |
| Phase 7 "verifier kernel" | Rust walks the stream and reduces it to `(missing_cap, taint_kind, arena_balance)`. The Omni kernel then maps those three numbers to an error code. Errors from this path report `line 1, col 1`. |
| VM (`OmniBinaryVm`) | Fuel and memory budgets, 64-deep calls, and in-VM host simulation. In simulation, `respond` returns `status * 1_000_000 + body`. |
| x86-64 ELF64 and Wasm emitters (`omni-aot`) | Rust. They compile the first function of a module only. They lower a 52-opcode allowlist and reject every other opcode, including all DB/KV/HTTP/DOM opcodes. On Wasm, `ISET` updates only the buffer length, and an `IGET` that cannot be resolved at compile time returns `0`. Byte-buffer contents therefore do not round-trip on Wasm. |
| Stage-1 compiler stream | A `u16` program of 19,731 words that turns tokens into an ELF64. It is **generated by Rust code** (`build_step7_stage1_compiler_stream`) and normally runs inside the Rust VM. On Linux x86-64, the workspace selftest also runs its native ELF on its own bytecode and checks that the output is byte-identical (106,242 bytes). It covers a subset of the language and is not `pure/compiler.omni`. |
| Live host (`omni serve`: TCP HTTP/1.1, file-backed DB/KV) | Rust HTTP, routing, and KV code over the 10-call `OmniNarrowHost` interface. File and DB paths are resolved inside a sandbox root, and escapes fail with `error[PATH_ESCAPE]`. The Phase C "host runtime" kernel is **not** on this path; it is exercised only by selftests. |
| Harness, agent driver, repair strategies, inspect, acceptance runner, CLI | Rust. `pure/tooling.omni` holds a few small decision kernels that these tools test. |

`run`, `eval`, `repl`, `serve`, `compile-surface`, `inspect`, `harness`, and `agent-driver` call wrappers with `pure_omni` in their names by default. Those wrappers are still the Rust compiler and verifier, with tiny kernels in front. The Phase B driver kernel is called with constant inputs, so it always approves. `omni-harness --legacy-rust` skips the wrappers.

### About the fixed-point numbers

Source code asserts the sizes and the Gen-1 == Gen-2 / Stage-1 == Stage-2 equalities. The FNV-1a64 hashes are printed by `pure-bootstrap` and recorded in the docs, but no test asserts them. All of them reproduce on this commit.

| Artifact | Size | FNV-1a64 | What it is |
|---|---|---|---|
| Phase D kernel `.omni_bc` | 159 words | `0x23B8D17257CCA9C4` | A 3-input decision kernel. "Gen-1" and "Gen-2" are both produced by the Rust compiler, so Gen-1 does not emit Gen-2. |
| Phase D kernel `.elf` | 824 bytes | `0xE221085777B8AC47` | The same kernel lowered two ways, once by the Rust x86-64 emitter and once by the Stage-1 stream. The two outputs agree. |
| 18-module suite | 14,559 words | `0x78462AE4C81DF408` | 7 `std` modules, 5 `pure` kernels, and 6 programs, compiled through the "Pure-Omni frontend" wrapper and through the Rust compiler. Both are the same Rust compiler. |
| Stage-1 == Stage-2 | 19,731 words / 106,242 bytes | `0xEAFC81F46B482FF8` | The fixed point of the Rust-generated Stage-1 stream. This is the strongest artifact here, and it is still generated by Rust. |

These are regression locks. They do not show that Omni compiles Omni.

## Repository layout

- `omni_rust_bootstrap.rs`: the standalone Stage-0 monolith (`rustc -O omni_rust_bootstrap.rs -o omni`, with no extra flags).
- `omni-workspace/`: the 8-crate workspace.
  - `omni-isa`: the opcode table, token ranges, contract-version constants, and the `@PACK5` codec.
  - `omni-ir`: the `u16` stream decoder and IR types.
  - `omni-verifier`: the production verifier (`verify_binary_function`, `verify_u16_stream`).
  - `omni-vm`: `OmniBinaryVm`.
  - `omni-assembler`: the `.omni_asm` line-to-packet encoder and the text assembler. The surface compiler emits through this encoder.
  - `omni-lang`: the surface compiler, host and server, repair agent, harness, inspect, acceptance runner, Pure-Omni wrappers, and the driver for the Omni verifier engine.
  - `omni-aot`: the Rust x86-64 ELF64 and Wasm emitters, a Wasm evaluator, the Stage-1 stream builder, and FNV-1a64.
  - `omni-cli`: `omnic`, `omni-harness`, and `omni-agent-driver`.
- `pure/`, `std/`: `.omni` sources (see "What runs where").
- `spec/`: acceptance goldens (24 positive and 15 negative in the manifest, plus `neg_circular_include.omni`, which is not in the manifest), the host interface, the error contract, trusted-core notes, the proof plan, and roadmaps. The acceptance runner uses embedded copies of the 39 manifest goldens; the manifest file itself is only sanity-checked.
- `spec.md`: the specification. Some check counts, some Section 6 opcode names, and the negative-golden count are stale. Where they disagree, `OMNI_ISA_TABLE` is authoritative.
- `LICENSE`: MIT.

## Quick start

On this commit with rustc 1.85.1 on Linux x86-64, the monolith selftest reports **416** checks and the workspace selftest reports **378**. Both built with 0 warnings. `pure-omni-diff` reports 47, `acceptance-diff` reports 39, and `cargo test --workspace` passes. Windows counts have not been measured; the native Stage-1 check runs only on Unix x86-64.

### Linux / macOS

```bash
rustc -O omni_rust_bootstrap.rs -o omni
./omni selftest
./omni pure-bootstrap
./omni pure-omni-diff
./omni acceptance-diff

cd omni-workspace
CARGO_INCREMENTAL=0 cargo build --workspace
cargo run -p omni-cli -- selftest
cargo test --workspace
```

### Windows (PowerShell)

```powershell
rustc -O omni_rust_bootstrap.rs -o omni.exe
.\omni.exe selftest
cd omni-workspace
$env:CARGO_INCREMENTAL=0; cargo build --workspace
cargo run -p omni-cli -- selftest
```

### Harness, agent driver, eval, serve

```bash
cargo run -p omni-cli --bin omni-harness -- --strict "fn main(a: i64) -> i64 { let b: i64 = a * 2; return b; }" 21
cargo run -p omni-cli --bin omni-agent-driver -- --strict "fn main(a: int) -> trit { let d = a - 10; let g = egate(d); return g; }" 25
cargo run -p omni-cli -- eval "#[cap(AI)] fn main(a: i64, b: i64) -> trit { let g = egate(a - b); return g; }" 30 10
cargo run -p omni-cli -- serve app.omni 127.0.0.1:8080 --max-requests 10 --db omni_host.kv
```

## Roadmap (none of this is done)

1. **Make the docs honest.** Update `spec.md`, `spec/PURE_SELF_HOST_ROADMAP.md`, `omni_full_status_audit.md`, and the CI step names so they match the counts and the guest/host split above.
2. **Verifier engine in lockstep.** Run `pure/verifier_engine.omni` as a shadow verifier on `compile`, `run`, and `serve`, and fail hard on any disagreement with the Rust verifier. Change the default only after a long clean run.
3. **Multi-byte loads and stores, with no new opcodes.** The agreed design tells the forms apart by operand shape. In each form, the second operand is the mode immediate:

   | Form | Operands | Meaning | Status |
   |---|---|---|---|
   | `ISET buf -4 v` / `ISET buf -8 v` | 3 | Append i32 / i64, little-endian | **Shipped** (`iset_i32` / `iset_i64`); stays unchanged. Wasm tracks only the length. |
   | `ISET buf -9 off v` | 4 | Patch a u64 at a byte offset | **Shipped** (`iset_patch_i64`); stays unchanged. Wasm tracks only the length. |
   | `ISET buf -2 off v` / `ISET buf -4 off v` | 4 | Patch a u16 / u32 at a byte offset | **Planned** (not implemented) |
   | `IGET buf -2 off` / `IGET buf -4 off` / `IGET buf -8 off` | 3 | Load a u16 / u32 / u64 from a byte offset | **Planned** (not implemented) |

   On this commit, a 4-operand `ISET` with `-2` or `-4` falls through to the generic byte-append path. `IGET` reads only its first two operands. Each new form needs an explicit branch on all four backends (VM, x86-64, Stage-1, and Wasm with real memory traffic), plus a golden that reads the bytes back. The existing `byte_buf_golden` must stay at 86 tokens. After that, `verifier_engine.omni` can move onto the new loads.

4. **Port in dependency order:** the token decoder, then the opcode table as data, then a direct packet encoder, then the surface frontend as many small loop-only functions that respect the limits above.
5. **Milestone 2:** a real two-pass `u16`-to-ELF64 compiler written in Omni, with a `stage2 == stage3` fixed point that does not use Rust compiler intrinsics. It should live in a new module so that the locked 18-module suite does not change.
6. **Shrink Stage-0** to process entry, the 10 host syscalls, the VM or loader, and the Rust reference twins used for differential testing.

HTTP, DB, and the repair agent belong in core by design. Only their syscall edge has to stay in Rust.
